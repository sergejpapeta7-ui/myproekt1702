Полный разбор кода — построчно

Каждая строчка разобрана: что она делает, зачем нужна и как работает. Разбор идёт сверху вниз — так же, как читает браузер.

001 Начало файла

Первые строчки документа. Браузер читает их первыми и понимает, как обрабатывать страницу.

1
<!DOCTYPE html>
Что: объявление типа документа. Зачем: без него браузер включит «quirks mode» — старый режим совместимости, где всё отображается непредсказуемо. Это не тег, а инструкция браузеру.
2
<html lang="ru">
Что: корневой элемент страницы. Внутри него лежит вообще всё. lang="ru" — говорит браузеру и поисковикам, что язык страницы русский (важно для озвучки и автоперевода).
3
<head>
Что: открывается блок «мозг страницы». Зачем: внутри хранятся служебные настройки, которые пользователь не видит. Закрывается на строке 12.

002 Настройки внутри <head>

Кодировка, мобильная адаптация, название вкладки, иконка, шрифты.

4
<meta charset="UTF-8">
Что: кодировка текста. Зачем: без этой строки русские буквы превратятся в «крякозябры». UTF-8 — универсальная кодировка, которая понимает почти все языки мира.
5
<meta name="viewport" content="width=device-width, initial-scale=1.0">
Что: настройка адаптации под мобильные. width=device-width — ширина страницы равна ширине экрана устройства. initial-scale=1.0 — масштаб 100% без начального увеличения. Без этой строки сайт на телефоне будет выглядеть как уменьшенная копия компьютерного.
6
<title>Полный разбор кода — построчно</title>
Что: название страницы. Где видно: на вкладке браузера, в закладках, в результатах поиска. Именно этот текст показывается, когда пользователь открывает много вкладок.
7
<link rel="icon" href="icon.jpg">
Что: подключение иконки сайта (favicon). rel="icon" — тип связи «иконка». href — путь к файлу. Иконка показывается слева от названия на вкладке.
8
<link rel="preconnect" href="https://fonts.googleapis.com">
Что: «предподключение» к серверу Google Fonts. Зачем: браузер заранее установит соединение с сервером, пока грузит остальную страницу. Это ускоряет загрузку шрифтов.
9
<link href="https://fonts.googleapis.com/css2?...&family=Montserrat..." rel="stylesheet">
Что: загрузка шрифта Montserrat с сервера Google. Зачем: чтобы страница на всех устройствах отображалась одним и тем же красивым шрифтом, а не системным по умолчанию.
10
<style> /* CSS идёт здесь */ </style>
Что: открывается встроенный блок CSS. Зачем: всё оформление страницы описано прямо здесь, без отдельного файла. Так проще копировать один HTML и всё работает.
11
</head>
Что: блок «мозг» закрыт. Всё, что после — будет видимым контентом.

003 CSS внутри <style>

Разбор правил оформления. Каждое правило = селектор + фигурные скобки со свойствами.

—
* { margin: 0; padding: 0; box-sizing: border-box; }
Что: «обнуление» отступов у ВСЕХ элементов (звёздочка = все). box-sizing: border-box — ширина элемента считается вместе с рамкой и отступами. Без этого width: 100px + padding: 20px даст реально 140px ширины, что ломает расчёты.
—
html { scroll-behavior: smooth; }
Что: плавная прокрутка. Зачем: когда пользователь кликает по якорной ссылке (например, #head), браузер плавно скроллит, а не «прыгает» мгновенно.
—
body { background: radial-gradient(ellipse at bottom, #1b2735 0%, #090a0f 100%); font-family: 'Montserrat', 'Segoe UI', sans-serif; color: #fff; padding: 2rem 1.5rem 6rem 1.5rem; }
background: радиальный градиент — тёмно-синий (#1b2735) внизу переходит в почти чёрный (#090a0f). Создаёт «космический» эффект.
font-family: сначала пробуем Montserrat, если нет — Segoe UI, если и его нет — любой системный без засечек.
color: белый текст по умолчанию.
padding: отступы — верх 2rem, право 1.5rem, низ 6rem (с запасом под кнопку «наверх»), лево 1.5rem. 1rem = 16px по умолчанию.
—
main { max-width: 1100px; margin: 0 auto; }
max-width: контент не растянется шире 1100px. margin: 0 auto — верх/низ без отступов, лево/право «auto» — блок автоматически центрируется по горизонтали.
—
.line { display: grid; grid-template-columns: 50px 1fr; gap: 1rem; }
display: grid — включаем сетку. grid-template-columns: 50px 1fr — две колонки: первая ровно 50px (для номера строки), вторая занимает всё оставшееся место (1fr = одна фракция). gap — отступ между колонками.
—
.line-code { white-space: pre; overflow-x: auto; }
white-space: pre — сохраняет пробелы и переносы строк как в исходнике. Без этого код «схлопнется» в одну строку. overflow-x: auto — если код не влезает, появится горизонтальный скролл.
—
.to-top { opacity: 0; pointer-events: none; } .to-top.visible { opacity: 1; pointer-events: auto; }
По умолчанию кнопка скрыта: opacity 0 (невидима) и pointer-events none (клики по ней не срабатывают). Когда есть класс .visible (его добавляет JS) — кнопка появляется (opacity 1) и начинает ловить клики (pointer-events auto). .to-top.visible — значит «элемент с классом to-top И классом visible одновременно».
—
@media (max-width: 700px) { ... }
Что: медиазапрос. Внутри этого блока — правила, которые работают, только если ширина окна 700px или меньше (телефоны). Всё, что здесь — уменьшенные размеры: шрифты, отступы, размеры блоков.

004 Меню навигации в <body>

Липкое меню, которое остаётся на месте при прокрутке.

—
<nav class="top-nav">
<nav> — семантический тег для навигации. Поисковики и скринридеры понимают: здесь меню. class="top-nav" — имя для CSS, чтобы оформить именно это меню.
—
<a href="#start">Начало</a>
<a> — ссылка. href="#start" — якорная ссылка: браузер найдёт на странице элемент с id="start" и плавно прокрутит к нему (благодаря scroll-behavior: smooth). Текст «Начало» — то, что видит пользователь.
—
.top-nav { position: sticky; top: 0; z-index: 20; }
position: sticky — элемент ведёт себя как обычный, но при скролле «прилипает» к верху. top: 0 — прилипает именно к верхнему краю. z-index: 20 — номер слоя: чем больше, тем выше элемент. Меню будет поверх контента.

005 Карточка разбора

Основной блок, внутри которого код и его объяснение.

—
<section id="start" class="block">
<section> — смысловой раздел страницы. id="start" — уникальный якорь для ссылки из меню. class="block" — общий класс для оформления (рамка, отступы, фон).
—
<h2><span class="num num-html">001</span> Начало файла</h2>
<h2> — заголовок второго уровня. Внутри <span> — маленький строчный контейнер, чтобы выделить только номер «001» цветной плашкой. Остальной текст остаётся белым.
—
<div class="line"> <div class="line-num">1</div> <div class="line-content">...</div> </div>
Внешний .line — сетка из двух колонок (номер + содержимое). .line-num — колонка с номером строки кода. .line-content — сюда идёт сам код и пояснение. Всё вместе даёт аккуратную таблицу «номер | код | пояснение».
—
<pre><code>...</code></pre>
<pre> — сохраняет все пробелы и переносы строк из исходника (иначе код схлопнется в одну строку). <code> — семантически говорит «это код». Внутри используются &lt; и &gt;, чтобы показать теги как текст.

006 JavaScript внизу страницы

Скрипт лежит в самом конце, перед </body>. Разбираем каждую строчку.

—
<script>
Зачем внизу: к моменту чтения скрипта весь HTML уже загружен. Если бы скрипт был вверху, он искал бы элементы, которых ещё нет.
1
const toTop = document.getElementById('toTop');
const toTop — создаём переменную, которую нельзя переприсвоить. document.getElementById('toTop') — ищем на странице элемент с id="toTop" и сохраняем ссылку в переменную. Теперь через toTop можем управлять этой кнопкой.
2
window.addEventListener('scroll', () => {
window — всё окно браузера. addEventListener('scroll', ...) — «слушай событие прокрутки». Второй аргумент — функция, которая выполняется КАЖДЫЙ раз, когда пользователь прокручивает страницу.
3
if (window.scrollY > 300) {
window.scrollY — сколько пикселей пользователь прокрутил вниз от самого верха. > 300 — проверяем, больше ли 300. Если да — выполняется следующая строка.
4
toTop.classList.add('visible');
classList — список классов элемента. .add('visible') — добавляет класс visible. В CSS прописано, что при наличии этого класса кнопка становится видимой (opacity: 1).
5
} else {
else — «иначе». Если пользователь прокрутил МЕНЬШЕ 300 пикселей — выполняется блок ниже.
6
toTop.classList.remove('visible');
.remove('visible') — убирает класс visible. Кнопка снова прячется (opacity: 0).
7
} });
Закрываем блок if/else и функцию-обработчик скролла.
8
toTop.addEventListener('click', () => {
Вешаем «слушателя» на клик по кнопке. Функция выполнится, когда пользователь нажмёт на кнопку «↑».
9
window.scrollTo({ top: 0, behavior: 'smooth' });
window.scrollTo — прокрутка окна. top: 0 — прокрутить к самому верху. behavior: 'smooth' — плавно, а не мгновенно.
10
});
Закрываем обработчик клика.
11
const observer = new IntersectionObserver((entries) => {
IntersectionObserver — встроенный «наблюдатель» браузера. Он следит, когда элемент появляется в зоне видимости. (entries) => {...} — стрелочная функция, которая вызывается при каждом изменении. entries — массив наблюдаемых элементов с их состоянием.
12
entries.forEach(entry => {
forEach — пробегаем по каждому элементу из массива entries. entry — текущий элемент с информацией о нём.
13
if (entry.isIntersecting) {
entry.isIntersecting — свойство, которое true, если элемент сейчас находится в видимой области окна. Если да — заходим внутрь.
14
entry.target.style.animationPlayState = 'running';
entry.target — сам элемент, за которым следим. .style — его встроенные стили. animationPlayState = 'running' — запускает CSS-анимацию. До этого она была на паузе, и блок был невидим.
15
} }); }, { threshold: 0.1 });
threshold: 0.1 — настройка наблюдателя: срабатывать, когда видно хотя бы 10% элемента. Если поставить 1 — ждал бы, пока элемент видно целиком.
16
document.querySelectorAll('.fade-in')
querySelectorAll — находит ВСЕ элементы с классом .fade-in на странице. Возвращает список (похож на массив).
17
.forEach(el => observer.observe(el));
forEach — проходим по всем найденным элементам. observer.observe(el) — подписываем каждый элемент на наблюдение. Теперь как только любой из них появится в зоне видимости — сработает наш обработчик.
18
</script>
Закрываем блок скрипта. Дальше — </body> и </html>.

007 Как HTML, CSS и JS связаны между собой

Теперь, когда мы разобрали каждый блок по отдельности, посмотрим, как три технологии соединяются в одно целое. Разберём три реальных примера с этой страницы.

Пример 1. Кнопка «Наверх» — связка HTML + CSS + JS

Самый наглядный пример. Здесь участвуют все три технологии: HTML создаёт кнопку, CSS прячет её и задаёт стиль, а JS показывает, когда нужно.

HTML — создаёт

Кнопка с двумя именами: class для CSS и id для JS.

CSS — прячет

По умолчанию кнопка невидима. Появляется только при классе .visible.

JS — управляет

Следит за скроллом и переключает класс .visible.

1
<!-- HTML: создаём кнопку --> <button class="to-top" id="toTop" aria-label="Наверх">↑</button>
class="to-top" — «имя» для CSS. По нему стили узнают, что это кнопка «наверх», и применят к ней свои правила.
id="toTop" — «имя» для JS. Уникальное, встречается только один раз. По нему скрипт найдёт именно эту кнопку.
aria-label="Наверх" — текст для скринридеров (невидимая подпись). Нужно для людей с ограниченными возможностями.
2
/* CSS: по умолчанию прячем кнопку */ .to-top { position: fixed; /* фиксируем в углу окна */ bottom: 30px; /* отступ снизу */ left: 30px; /* отступ слева */ opacity: 0; /* невидима */ pointer-events: none; /* не реагирует на клики */ }
position: fixed — кнопка «приклеена» к экрану, не движется при прокрутке.
opacity: 0 — полностью прозрачная, пользователь её не видит.
pointer-events: none — отключает реакцию на мышь. Даже если случайно кликнуть в этом месте — ничего не сработает. Это важно, потому что невидимая кнопка не должна мешать.
3
/* CSS: когда есть класс .visible — показываем */ .to-top.visible { opacity: 1; /* теперь видна */ pointer-events: auto; /* снова реагирует на клики */ }
.to-top.visible — правило сработает, только если у элемента ОДНОВРЕМЕННО есть оба класса: to-top и visible.
Класс visible изначально не задан в HTML. Его добавит JavaScript, когда пользователь прокрутит страницу вниз. Тогда кнопка «проявится».
4
// JS: находим кнопку по id const toTop = document.getElementById('toTop'); // JS: следим за прокруткой window.addEventListener('scroll', () => { if (window.scrollY > 300) { toTop.classList.add('visible'); // ← показываем } else { toTop.classList.remove('visible'); // ← прячем } });
getElementById('toTop') — JS ищет кнопку по id и запоминает ссылку.
classList.add('visible') — добавляет класс visible. CSS тут же «видит» изменение и показывает кнопку.
classList.remove('visible') — убирает класс. Кнопка снова прячется.
Что произошло: JS не меняет цвет кнопки напрямую — он просто переключает класс. Всё оформление остаётся в CSS. Так код чище и логичнее.

Пример 2. Анимация появления блоков — связка CSS + JS

Здесь HTML вообще не участвует: у нас уже есть блоки с классом .fade-in. CSS описывает анимацию, но ставит её на паузу. JS запускает её, когда блок появляется в зоне видимости.

1
/* CSS: описываем анимацию и ставим на паузу */ .fade-in { opacity: 0; /* невидим */ transform: translateY(20px); /* сдвинут вниз */ animation: fadeInUp 0.8s ease forwards; animation-play-state: paused; /* ← анимация НА ПАУЗЕ */ } @keyframes fadeInUp { to { opacity: 1; /* станет видимым */ transform: translateY(0); /* вернётся на место */ } }
animation — задаёт анимацию: имя fadeInUp, длительность 0.8s, плавность ease, удержать финал (forwards).
animation-play-state: paused — ключевая строка. Анимация создана, но стоит на паузе. Блок выглядит как opacity: 0 — невидим.
@keyframes fadeInUp — описывает, к чему анимация должна привести: сделать видимым и вернуть на место.
2
// JS: запускаем анимацию, когда блок попал в поле зрения const observer = new IntersectionObserver((entries) => { entries.forEach(entry => { if (entry.isIntersecting) { entry.target.style.animationPlayState = 'running'; // ← снимаем с паузы } }); }); document.querySelectorAll('.fade-in').forEach(el => observer.observe(el));
IntersectionObserver — «наблюдатель», который сам сообщает браузеру, когда элемент попал в зону видимости.
animationPlayState = 'running' — эта строчка снимает анимацию с паузы. Как только это произошло — CSS-анимация плавно проявляет блок.
querySelectorAll('.fade-in') — находит все блоки, которые должны появляться с анимацией, и подписывает каждый на наблюдение.
Что произошло: CSS нарисовал анимацию, но остановил. JS в нужный момент даёт команду «поехали».

Пример 3. Меню с якорями — связка HTML + CSS (без JS)

Не всё требует JavaScript. Вот пример, где HTML и CSS справляются сами.

1
<!-- HTML: ссылка с якорем --> <a href="#head">HEAD</a> <!-- HTML: секция с id, на которую ведёт ссылка --> <section id="head">...</section>
href="#head" — «прокрутить к элементу с id="head"».
id="head" — якорь, к которому ведёт ссылка. Браузер сам находит нужное место.
2
/* CSS: делаем прокрутку плавной */ html { scroll-behavior: smooth; }
scroll-behavior: smooth — одна строчка, которая делает прокрутку плавной. Без неё браузер «прыгал» бы мгновенно к якорю.
Что произошло: HTML связал клик и место, CSS добавил плавность. JavaScript не нужен вообще.
Главное правило: HTML, CSS и JS — это три разных языка, которые решают разные задачи. HTML создаёт элементы. CSS описывает, как они выглядят. JS управляет ими во времени.

Связываются они через два «моста»: class — для CSS, id — для JS. Поэтому в HTML-элементах всегда пишут и то, и другое, если хотят, чтобы элемент и выглядел красиво, и реагировал на действия.
